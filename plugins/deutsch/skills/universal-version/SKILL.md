# Build the Universal Version

Derived from *The Fabric of Reality* by David Deutsch (Chapter 6 (Universality and the Limits of Computation)).

## Core Principle

Deutsch's Turing principle states that it is possible to build a single physical machine whose repertoire includes any computation that any other physical object can perform, and that this kind of universality, one general purpose device outperforming an unbounded pile of special purpose ones, is not a lucky accident of computers but a deep fact about how comprehensible systems get built. The same logic applies below the level of physics. A rule, tool, or explanation built for the whole class a situation belongs to will keep working on cases you have not yet met, while a rule built only for the case in front of you has to be rebuilt every time reality throws something new at it.

## Framework

### Step 1: Notice the Special Case Signal

Catch yourself writing a rule, script, or explanation that only works because of one detail specific to the case in front of you.

### Step 2: Name the Class This Case Belongs To

State the general category of situations this particular case is one member of.

### Step 3: Design for the Whole Class

Build the rule, tool, or explanation so that it handles any member of that class, including ones you have not encountered yet.

### Step 4: Accept the Higher Upfront Cost

Expect the general version to take longer to build than the patch. That cost buys you not having to keep resolving the same class of problem.

### Step 5: State the Boundary Out Loud

Say explicitly what is still outside the general version's repertoire, rather than letting people assume it covers everything.

## Anti-patterns

- Piling up special cases instead of stepping back to find the general rule they are all instances of.
- Assuming universal means covers literally everything rather than covers the whole relevant class.
- Refusing to invest in a general solution because the special case patch looks cheaper today, then paying for it again on the next case.

## Output shape

The class of situation named, the general rule or tool designed to cover it, and an explicit statement of what is still outside its scope.
