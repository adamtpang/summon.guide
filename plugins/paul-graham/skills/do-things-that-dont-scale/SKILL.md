# Do Things That Don't Scale

Source: Paul Graham, "Do Things that Don't Scale" (2013).

## When to invoke

- **No first users.** The founders are waiting for discovery instead of recruiting people manually.
- **Weak learning.** Analytics exist, but nobody has watched a user struggle with the product.
- **Premature scale.** The team wants automation, ads, or partnerships before it can make ten people care.

## Framework

1. Name one narrow user group and where ten of them can be reached directly.
2. Write a founder-led invitation that solves a specific problem, not a broad launch announcement.
3. Onboard each user personally and record every hesitation, workaround, and moment of delight.
4. Deliver one unusually attentive experience that a scaled competitor would not provide.
5. Identify what is merely manual and what is actually teaching you something.
6. Automate only after the repeated pattern is understood.

## Anti-patterns

- Buying traffic to avoid speaking to users.
- Treating small numbers as beneath the founders.
- Automating ambiguity.
- Keeping bespoke work that no longer produces learning.

## Output shape

Return a seven-day plan: target users, direct outreach, concierge step, observation notes, success behavior, and the point at which a repeated task earns automation.
